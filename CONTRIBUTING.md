# Contributing

Resolvewhy is a research prototype with a deliberately narrow verified semantic
fragment. Changes should preserve the distinction between verified facts,
incomplete evidence, and resolver-native observations.

## Development setup

```bash
python -m pip install -e ".[pip-resolvelib]"
```

The production core itself uses the standard library; the optional extra is
needed for the pip/resolvelib adapter and its integration tests.

## Required checks

```bash
python -m unittest discover -s tests -v
python -m unittest research.test_reproducibility -v
python research/run_reproducibility.py --json
```

The research runner is network-free. Do not add live package-index,
resolver-cache, or machine-specific inputs to it.

## Change expectations

- Add a focused regression test for each behavior change or bug fix.
- Keep trace validation fail-closed. Unknown or incomplete evidence must not be
  upgraded to VERIFIED_SAT or VERIFIED_UNSAT.
- Keep evaluation domains, runtime contexts, resolution policy, and candidate
  coverage semantically distinct.
- Do not present a resolver failure, an empty unscoped candidate list, or a
  passing unit test as a general correctness proof.
- Update the relevant documentation whenever an established guarantee, boundary,
  or reproducibility procedure changes.

Generated bytecode, virtual environments, build output, and reproducibility
result directories are intentionally ignored and must not be committed.
